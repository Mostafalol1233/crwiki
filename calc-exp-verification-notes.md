## Logic issues found in code (to fix in Phase 3)
1. Profile lookup regex `md.match(/(\d[\d,]+)\s*EXP/)` captures the first EXP on the page — profile page shows "28179536 EXP" next to rank name, which is the CURRENT rank's progress number, NOT total EXP. Official z8games profile API returns TotalExp; the markdown parse may misread it. Need double-check with a real profile scrape.
2. Manual EXP input: calculator treats entered number as cumulative total EXP (consistent). OK.
3. getExp fallback order: r.expRequired > db.exp_required > CF_EXP_THRESHOLDS. DB values may be wrong/0 — mergeRanks correctly forces static table for thresholds. OK.
4. default destination = currentIdx+1. When no manual EXP entered and no rank selected, currentIdx=-1 and availableDests = all ranks → defaultDestId="" and destinationRank=null; results hidden until selection. Acceptable.
5. progressPct divides by (end-start) where end=destination cumulative. Correct semantics for cumulative values.
6. expNeeded when currentExp null: destination - currentRankExp. Correct.
7. AI tips: uses puter.js CDN — external dependency; low severity.
