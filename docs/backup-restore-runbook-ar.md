# دليل النسخ والاستعادة الآمن لمشروع CrossFire Wiki

## الغرض ونطاق الدليل

هذا الدليل يشرح طريقة حفظ نسخة قابلة للاستعادة من الشيفرة وإعدادات النشر والبيانات التحريرية، ثم التحقق منها قبل أي استعادة. لا يحتوي الدليل على كلمات مرور أو مفاتيح خدمة أو رموز جلسات، ولا ينشئ مهمة مجدولة تلقائيًا. يجب تنفيذ العمليات الحساسة من حسابات المالك وبصلاحياتها الرسمية فقط.

> قاعدة أساسية: لا تُحفظ الأسرار داخل Git أو ملفات النسخ. تُحفظ الأسرار في مدير متغيرات البيئة الرسمي، ويُعاد إدخالها يدويًا بعد الاستعادة أو تدويرها إذا ظهرت في مكان غير آمن.

## ما الذي يجب نسخه

| المجال | ما يُحفظ | ما لا يُحفظ داخل الملف |
|---|---|---|
| الشيفرة | فرع Git، سجل الالتزامات، وملفات المشروع غير السرية | ملفات البيئة، مفاتيح الخدمة، رموز الإدارة، أو بيانات الاعتماد |
| قاعدة البيانات | الجداول التحريرية، سجلات المحتوى، إعدادات المسابقة، وسجل التعديلات وفق سياسة الاحتفاظ | كلمات المرور، رموز الدخول، أرقام المشاركين، أو إثباتاتهم خارج التخزين المصرح به |
| الوسائط | قائمة عناوين الصور وملفات الوسائط ومصدر كل ملف | مفاتيح التخزين أو روابط موقعة مؤقتة منتهية الصلاحية |
| النشر | اسم المشروع، إعداد البناء، سجل آخر Preview ناجح، ولقطات إعدادات غير حساسة | قيم متغيرات البيئة أو رموز الحماية |
| التحرير | ملفات المسودات ومصادرها وتواريخ مراجعتها | أي محتوى غير منسوب إلى مصدر أو مسودة تم تحويلها إلى منشور دون مراجعة |

## قبل أخذ النسخة

يجب أولًا التأكد من أن فرع العمل نظيف أو أن كل تغيير غير مدموج موثق في التزام مستقل. بعد ذلك يُشغّل فحص الأنواع والبناء واختبارات التدخين، ويُحفظ رقم الالتزام ووقت الاختبار. لا تُؤخذ نسخة من قاعدة البيانات أثناء عملية تحرير جماعية غير مستقرة، ولا يُعتبر Preview بديلًا عن نسخة البيانات.

## نسخة الشيفرة غير الحساسة

يُنشأ أرشيف من Git بعد التأكد من عدم وجود ملفات بيئة أو مخرجات مؤقتة. مثال آمن يستخدم اسمًا عامًا للفرع ولا يطبع محتويات الأسرار:

```bash
git status --short
git log -1 --oneline
git archive --format=tar.gz --output=crwiki-source-YYYYMMDD.tar.gz HEAD
```

بعد إنشاء الأرشيف، يجب فحص قائمة الملفات داخله بحثًا عن أسماء مثل `.env` أو `secret` أو `token` قبل رفعه إلى مكان التخزين. لا تُرفع الأرشيفات إلى مستودع عام.

## نسخة قاعدة البيانات

تُؤخذ نسخة قاعدة البيانات من أداة النسخ الرسمية للمشروع أو من لوحة Supabase بصلاحيات المالك. يجب اختيار الجداول المطلوبة فقط إن كانت الأداة تسمح بذلك، مع الالتزام بسياسة الاحتفاظ وعدم نسخ سجلات الهوية أو الإثباتات إلا عند الحاجة التشغيلية والقانونية. لا تُطبّق أي ملف ترحيل أو استعلام استعادة شامل قبل فحص مخطط قاعدة البيانات الحي ومقارنة أسماء الأعمدة والقيود.

تُخزّن نسخة البيانات مشفرة، ويُحفظ معها سجل وصفي يذكر وقت النسخ، نطاق الجداول، رقم النسخة، ونتيجة التحقق. لا يوضع مفتاح التشفير أو كلمة المرور في سجل Git أو في هذا الملف.

## نسخة الوسائط

يجب الاحتفاظ بقائمة دورية بالعناوين الأصلية للصور وعناوين المصدر ونوع الاستخدام. عند فقد ملف، يُستعاد من مخزن الوسائط الرسمي أو من المصدر الموثق، وليس من صورة عشوائية. تُراجع الروابط التي تستخدم HTTP وتُحوّل إلى HTTPS إذا كان المصدر يدعم ذلك، مع عدم تجاوز أخطاء شهادات TLS أو تحميل ملفات من مصادر غير موثوقة.

## الاستعادة الموصى بها

تبدأ الاستعادة في بيئة Preview أو بيئة اختبار منفصلة، ولا تبدأ على النطاق العام. يُستعاد ترتيب المكونات وفق الجدول التالي:

| المرحلة | الإجراء | معيار النجاح |
|---|---|---|
| 1 | استعادة الشيفرة إلى فرع اختبار | يطابق رقم الالتزام المسجل |
| 2 | تثبيت الاعتماديات وتشغيل فحص الأنواع والبناء | لا توجد أخطاء بناء أو تغييرات غير متوقعة |
| 3 | ضبط متغيرات البيئة يدويًا من مدير الأسرار الرسمي | لا تظهر القيم في السجل أو الواجهة |
| 4 | استعادة الجداول الضرورية بعد فحص المخطط والقيود | تُقبل البيانات دون كسر RLS أو القيود |
| 5 | فحص الصور والروابط والمحتوى المنشور | لا توجد صور مفقودة أو روابط داخلية مكسورة في العينة |
| 6 | اختبار تسجيل الدخول والمسارات العربية وصفحات الإدارة في Preview | تبقى الجلسة واللغة والمسارات مستقرة |
| 7 | اعتماد النتيجة من المالك | لا تتم ترقية النشر العام تلقائيًا |

## تحقق ما بعد الاستعادة

يجب فحص الصفحة الرئيسية، البحث، الأسلحة، الخرائط، المودات، الرتب، المرتزقة، المقالات، الأخبار، الأحداث، البائعين، الخدمات، الملف الشخصي، الدعم، المنتدى، ومركز المحتوى على عرض هاتف قريب من 390 بكسل. كما يجب فحص صفحة المسابقة في Preview فقط مع إبقاء بيانات المشاركين وأرقام الهواتف والنتائج غير منشورة قبل اعتماد الإعدادات.

تُفحص أيضًا مسارات `/ar` والمسارات الإنجليزية، وتُراجع الروابط التي تحتوي على بادئة عربية مكررة. يجب أن تعيد خريطة الموقع وملف robots حالة نجاح، ويجب أن تحتوي صفحات المقالات والأحداث المنشورة على عنوان ووصف وصورة مشاركة عند توفرها. لا يعني نجاح الفحص ضمان الفهرسة في محركات البحث، بل يعني أن الإشارات التقنية الأساسية متاحة للفحص.

## سياسة الاحتفاظ والإلغاء

يُحتفظ بنسختين على الأقل من آخر نسخ سليمة، مع نسخة أقدم لاختبار الرجوع الزمني عند الحاجة. تُحذف النسخ القديمة وفق سياسة مكتوبة وبعد التأكد من عدم ارتباطها بحادث أمني أو متطلب قانوني. إذا اشتبه المالك في انكشاف أي سر، فلا يُعاد استخدامه من النسخة؛ يجب تدويره من مدير الأسرار قبل إعادة التشغيل.

## الأتمتة لاحقًا

إذا تقرر إنشاء نسخ دورية أو مراقبة تلقائية، يجب أولًا تحديد التكرار، مكان التخزين، مدة الاحتفاظ، جهة التنبيه، والتكلفة المقبولة. النسخ الدورية منخفضة التكرار يمكن تشغيلها عبر مهمة مجدولة بسيطة، أما المراقبة المتكررة أو التحقق كل دقائق فيحتاج خدمة مستمرة أو وظيفة Cron داخل بيئة استضافة مناسبة. لا تُنشأ أي جدولة أو موصل جديد لهذا المشروع من هذا الدليل وحده.
